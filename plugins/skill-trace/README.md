# skill-trace

Claude가 질문마다 어떤 스킬을 왜 골랐는지, 어떤 플러그인 기능을 썼는지 옆 패널에 보여 주는 Claude Code mod입니다.

- **패널** (`/skill-trace` 로 다시 열기): 질문 → 섹션 → 항목의 트리입니다. 최근 30건까지 보관합니다.

  ```
  ▾ Session
    ├ ID          831fa453-ab54-43f2-94fa-8eb63dc64ce0
    ├ Model       Opus 5.5
    ├ Permissions bypassPermissions
    └ Folder      C:\workspace\personal\agent-lens

  ▾ Q8 · 14:53:02 → 14:55:51 · 2m 49s
    업데이트 했어

   ▾ Skills 1
     └ ponytail:ponytail-help
       0.1.3 이유 기록 도구가 패널에 이유를 붙이는지 실측
   ▸ Hooks 7
  ▸ Q7 [Image #4] 지금 상태로 보여 개선 진행 해…
    14:50:01 · 4m 12s · MCP 6 · Hooks 135
  ```

  - 맨 위 Session 영역은 지금 세션의 ID, 모델(`/model` 이 보여 주는 이름), 권한 모드, 작업 폴더를 보여 줍니다. ID와 폴더가 있으면 `claude --resume <ID>` 로 이 세션에 돌아올 때 어느 폴더에서 열지 알 수 있습니다. 머리줄을 누르면 접혀서 `▸ Session · Opus 5.5 · bypassPermissions` 한 줄만 남습니다. ID와 모델은 세션 시작과 프롬프트마다 다시 읽어 `/clear`·`/model` 뒤에도 맞습니다. 권한 모드는 직접 묻는 API가 없어서 프롬프트나 도구 호출 때 훅 입력으로 받습니다. 그래서 shift+tab 으로 바꾼 모드는 다음 프롬프트나 도구 호출부터 보입니다.
  - 최신 질문이 펼쳐지고, 지난 질문은 질문 한 줄(패널 폭에서 `…` 으로 잘림)과 시작 시각·소요 시간·금액·항목 수 한 줄로 접힙니다. 이 줄도 폭에서 잘리므로 금액을 항목 수보다 앞에 둡니다. 질문 줄을 누르면 펼치고(긴 질문은 전체 텍스트까지), 다시 누르면 접힙니다. 질문마다 상태가 따로 유지되어, 하나를 펼쳐도 다른 질문은 그대로입니다(손대지 않은 질문은 최신만 펼침).
  - 펼친 질문은 시작 → 끝 시각과 소요 시간을 보여 줍니다(진행 중이면 "running"). 끝 시각은 그 질문의 마지막 메인 턴이 끝난 시각입니다.
  - 펼친 질문 아래 `↑ Show in chat` 을 누르면 대화 창이 그 질문 줄로 스크롤됩니다. 대화가 길어져도 스크롤을 올려 찾지 않아도 됩니다. 엔진이 대화를 직접 그리는 화면(터미널 fullscreen, 데스크톱 앱)에서만 움직이고, 일반 터미널 화면(`CLAUDE_CODE_NO_FLICKER=0`, tmux)이나 압축·`/clear` 로 그 줄이 사라진 뒤에는 이유를 토스트로 알립니다. 0.4.0 전에 기록된 질문에는 이 버튼이 없습니다.
  - 섹션 줄(Skills·MCP·Subagents·Tools·Hooks·Commands)도 눌러서 접고 펼칩니다. 양이 많은 Tools·Hooks 섹션은 기본으로 접혀 있습니다.
  - 이유·출처 같은 설명 줄은 항목 이름 아래 같은 열로 들여 써서, 줄이 넘쳐도 정렬이 유지됩니다.
  - 스킬: 이름과 고른 이유. 사용자가 `/명령`으로 직접 실행한 스킬은 "run by user", 이유 줄이 없으면 "no reason given"
  - MCP: 서버(플러그인)·도구별 호출 횟수
  - 서브에이전트: 타입별 호출 횟수
  - Tools: 기본 도구(Bash·Read·Edit …)의 도구별 호출 횟수. Read·Edit·Write·NotebookEdit 아래에는 다룬 파일을 세션 작업 폴더 기준 경로와 횟수로 나열합니다. Skill·Agent·MCP 호출은 각자의 섹션에서 셉니다
  - Cost: `Chat $0.21` 아래에 모델별 요청 수와 토큰, 그리고 `skill-trace $0.0001 (est.)` (규칙·이유 도구 정의가 요청마다 따라간 몫과 이유 호출 출력, 추정). 금액은 API 정가 환산이며 구독 요금과는 다릅니다
  - 훅: 훅 이벤트와 주입된 텍스트 첫 줄, 그리고 `← 출처 후보`(그 이벤트에 훅을 등록한 플러그인·settings 훅 명령 이름). 아무것도 주입하지 않고 실행만 된 훅은 `(nothing injected)` 으로 흐리게 표시
  - 커맨드: 실행한 슬래시 커맨드
  - 서브에이전트 안에서 일어난 스킬·MCP 호출은 `(sub)` 표시
- **이유 기록 도구**: mod 가 `mcp__skill-trace__reason` 도구를 등록하고, 시스템 프롬프트에 "Skill 을 부를 때 같은 응답에서 이 도구로 `{ skill, reason }` 을 남긴다"는 규칙을 더합니다. 이유가 도구 인자로 오므로 채팅 본문에 이유 줄이 섞이지 않습니다(도구 호출 한 줄만 보임). 최종 답변에 `[스킬근거] <스킬명>: <이유>` 줄이 있으면 그것도 읽습니다.

## 설정

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `start` | `on` | `off` 면 세션 시작 때 패널을 열지 않습니다. `/skill-trace` 로 열 때만 보입니다. |
| `reason` | `on` | `off` 면 이유 기록 도구와 규칙을 넣지 않습니다. 스킬 이유는 "no reason given"로 보입니다. |
| `cost` | `on` | 질문마다 `Cost` 섹션에 쓰인 모델, API가 알려 준 토큰(입력·출력·캐시 읽기·쓰기)과 정가 환산 금액(Chat), 그 가운데 skill-trace가 더한 몫(추정)을 보여 줍니다. **`reason` 이 켜져 있을 때만** 켤 수 있고, `reason` 이 꺼지면 함께 꺼집니다. |

`/config` 메뉴에서 바꾸거나, 터미널에서 설정합니다.

```
claude plugin configure skill-trace@agent-lens
claude plugin install skill-trace@agent-lens --scope user --config start=off
```

mod 전체를 켜고 끄려면 `claude plugin disable skill-trace@agent-lens --scope user` / `enable` 를 씁니다.

## 한계

- 비용은 API 정가 환산입니다(claude-api 스킬의 모델 표, 2026-10-06 기준). 구독은 토큰당 과금되지 않습니다. 캐시 쓰기는 TTL 구분이 없어 1시간 TTL(2×)로 셉니다. 가격표에 없는 모델은 "price unknown"으로 표시하고 금액에 넣지 않습니다.
- skill-trace 몫은 추정입니다: 규칙·도구 정의 토큰은 글자 수로 어림하고(실제 토크나이저 아님), 캐시에서 읽힌다고 보고 셉니다.
- 이유는 모델의 자기 보고입니다. 실제 판단 과정의 기록이 아닙니다.
- 질문 도중에 새로 입력한 프롬프트는 새 질문을 시작하므로, 그 턴의 나머지는 새 질문에 기록됩니다.
- `/clear` 로 대화를 비워도 기록은 지워지지 않아 질문 번호가 이어집니다.
- 엔진은 훅 한 번 한 번이 어느 플러그인의 것인지 알려 주지 않습니다. 그래서 출처는 "그 이벤트에 훅을 등록한 곳"을 후보로 보여 줍니다(도구별 matcher 는 아직 보지 않음). 출처 후보는 마켓플레이스로 설치했을 때만 나옵니다(`--plugin-dir` 로 띄우면 생략).
- "검토했지만 쓰지 않은 스킬"은 관찰할 수 없습니다.
- 세션 도중 mod 를 처음 켜거나 끄면 시스템 프롬프트가 바뀌어 프롬프트 캐시가 한 번 초기화됩니다.
- 터미널 폭이 좁으면 패널은 자리가 날 때까지 기다립니다.

Install instructions are in the [repository README](../../README.md).
